# 核验升代命运说明（当日锁死）

- 锁定日期：2026-11-22
- 适用产品：保证金笼（本仓 `11-bondcage`）
- 命运选择：**乙路径 —— 旧票留史，写口只认新票指针**
- 锁死性质：本说明是升代正确性的唯一口径。代码中的单一事实源为
  `backend/generation_policy.py`（`PATH_CODE = "B"`）。任何与本说明不一致的
  写操作一律记「升代偏航」并拒写（HTTP 409）。禁止第三路，禁止甲乙混用。

## 一、票号（核验票）定义

1. 每条核验结论生成一张票，票号格式 `ATT-{cage_code}-g{attest_gen}`，全表唯一。
2. 票号一经写出不可变更、不可复用；笼代只增不减。
3. `cages.current_ticket_ref` 是该笼**唯一**的当前有效票指针；解笼与罚没只认
   该指针指向的票。指针为空（升代后、新核验前）时，任何解笼/罚没一律拒写。

## 二、乙路径口径（锁定，禁止偏离）

1. **旧票留史只读**：升代后旧代票号在查询口（`GET /api/attestations`、
   `GET /api/cages/{id}`、审计页）仍然可查，带 `current=false` 与所属笼代标记，
   作为史迹永久保留，不物理删除、不拒收查询。
2. **写口只认新票指针**：`POST /api/releases` 与 `POST /api/forfeits` 只接受
   `current_ticket_ref` 指向的当前笼代票：
   - 请求显式带 `ticket_ref` 时，必须等于当前指针，否则 409「升代偏航：旧票不得驱动写口」；
   - 请求不带 `ticket_ref` 时，服务端按当前指针解析；指针为空则 409 拒写；
   - 旧票号永远无法再驱动任何出金（解笼拨付或罚没）。
3. **未切指针前旧代零改**：不调用升代接口，笼代、票指针、旧结论的行为与本说明
   生效前完全一致——旧代核验仍按原规则驱动解笼/罚没，对账口径不变。
4. **升代即切指针**：`POST /api/cages/{id}/generation-upgrade` 在笼锁内一次完成：
   笼代 +1、状态回置「已冻结」、`current_ticket_ref` 置空。新核验落票后指针指向
   新票，旧票随之转为只读史迹。升代前若本代已有解笼/罚没落账，拒升（资金已出笼，
   不得用升代抹账）。
5. **同笼升代抢笼锁**：两人同时升同一只笼，后到者抢 `cage:{id}` 锁失败，只在
   `contention_log` 留争用痕，不写任何业务数据（笼代不得跳两次）。
6. **对账只认真金白银的当前代**：对账仍按笼代汇总 releases/forfeits；旧代留史票
   不产生任何金额动作，不存在「旧票绿灯而驱动已换新票」的混用窗口。

## 三、明确禁止的混用形态（出现即偏航，拒写并留痕）

- 旧票号仍能驱动解笼拨付成功或罚没成功；
- 对账按旧票显示绿灯，而实际驱动票已换成新票；
- 升代后旧票在查询口消失（那是甲路径，与本仓锁定的乙路径冲突）；
- 只改核验页提示文案而无写口强制（本说明由服务端 policy 强制，不靠页面提示）；
- 任何第三条路径（如双票并行均可驱动、新旧票按时间自动切换等）。

## 四、五页同源

核验页、入笼页、解笼页、罚没页、审计页展示的票号与笼代必须取自同一后端事实
（`attestations.attest_ref` / `cages.current_ticket_ref` / `cages.generation` /
`generation_events` / `audit_trail`），前端不得自行拼票号或缓存旧指针。

## 五、验收顺序（与测试绑定）

1. 先造「旧代结论卡住新材料」假绿事故夹具，实打升代接口看到假绿（接口缺失即红）；
2. 三红：升代无法重裁、旧票仍能驱动解笼、双会话同升无争用控制；
3. 三红齐后才准改五个服务与核验/入笼两页；
4. 收尾三红转绿，并逐页核对五页票号与笼代同源。
